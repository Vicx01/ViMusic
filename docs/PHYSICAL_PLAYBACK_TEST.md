# Physical-device playback test (experimental InnerTubeX)

This is a test plan, not a record of successful device playback. Never uninstall an existing app or clear app data to make installation work.

1. Download `vimusic-debug-apk` from a successful Android CI run for the branch. It uses package `it.vfsfitvnm.vimusic.debug`, separate from the normal release app. CI debug signing keys are ephemeral; if installation reports an incompatible signature, **stop** rather than uninstalling the existing debug app. Use a fresh test device/profile or a locally built APK signed with the same existing test key. Do not install the CI release APK as a production release: the project currently signs that variant with a debug key.
2. On an Android 8.0+ physical device with working network, install the debug APK without deleting existing data. In Player & Audio, turn on **Experimental InnerTubeX playback**. Force-stop the debug app and relaunch it so the playback service reads the new setting. Turning the switch off and force-stopping/relaunching returns to the legacy provider.
3. Play a publicly available song longer than one minute from search. Verify playback starts and continues beyond **30 seconds of real time**, then seek forward and backward, and play through track completion. Record device model, Android version, app commit, network type, elapsed times and observed result. The log message `InnerTubeX progressive stream resolved` indicates the new resolver returned a stream; a `trying legacy provider` message means fallback occurred, so that attempt does **not** prove InnerTubeX playback.
4. Repeat with an interruption (pause/resume, background/foreground and a brief network loss/reconnection); record whether playback resumes, fails visibly or falls back. Verify queue order and library items remain intact, and test switching back to legacy after restarting the service. A real HTTP 403/416 recovery should be reported separately from a generic interruption; do not manufacture or publish signed URLs.
5. Report only the sanitized `ViMusicPlayback` status messages, HTTP status codes, and the results above. Do not share full logcat, cookies, tokens, signed URLs, API keys, request headers or raw server responses. Device tests on a new debug package cannot by themselves prove migration of an existing release database.

Synthetic CI tests exercise recovery and playback using local fixture audio; they do not establish that a live YouTube client, BotGuard challenge, or CDN works on the device. TTML integration remains gated on validated live playback.
